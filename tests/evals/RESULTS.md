# Eval results

Head-to-head runs of Claude Code **with** the skill versus **without** it (same model, prompt and input files), graded by an independent Claude agent against written criteria. October 2026, model `claude-opus-5-5`.

## Method

- **Tasks:** four realistic requests from [`evals.json`](evals.json), each run as a headless Claude Code session (`claude -p`) in a fresh folder, once with `--plugin-dir ./plugins/linkedin` and once without. The prompts are plain English (no slash commands), so they also test whether the skill activates on its own.
- **Inputs:** synthetic personas. Maya Chen is a data analyst moving into ML engineering; Priya Raman is a fractional CFO. Priya's LinkedIn data archive and analytics export are generated by [`make_fixtures.py`](../make_fixtures.py) to mirror LinkedIn's real export formats.
- **Grading:** a separate agent read each run's final answer and output files, checked every assertion with cited evidence, recomputed numbers against the ground truth, ran `check.py` on drafted posts, and spot-checked recommended people with web search.
- **Prompts** end with "I can't answer follow-up questions right now", because headless runs can't reply. Real users get clarifying questions where they help.

\*After the iteration-2 fixes described below. Costs are at API list price.

**Triggering:** 10 of 10 correct. The skill activated for 5 plain-English LinkedIn requests (headline, post, who to follow, falling impressions, About section). It stayed out of 5 near-misses: a cover letter, a tweet thread, a LinkedIn scraping script, a newsletter summary, and an email to a recruiter.

## What the graders found

**Without the skill**, Claude was capable but less reliable:
- **Fabrication.** In the ideas task, the "ready-to-publish" post invented a week-by-week account of client work that isn't in the user's data.
- **Unverifiable people.** In the follow task it gave no profile links, and one recommended person couldn't be found at all.
- **Internal inconsistency.** In the audit, the headline score didn't match its own category breakdown (38/100 claimed, 37/120 summed), and an About section labeled "≈1,900 characters" was actually 2,176. It also stated tools the user never listed as facts.
- **Analysis claims.** In the analytics task, two report claims contradicted its own scorecard.

**With the skill**, every assertion passed:
- every analytics number recomputed correctly;
- sample sizes and confounders were stated;
- drafted posts scored 100/100 on the checker, with every fact traced to the user's archive;
- the 6 spot-checked people were real and their roles matched;
- all claimed post dates decoded correctly.

**Where Claude alone did better:** it was faster and cheaper. It also added useful extras the skill now covers too: a per-job fit assessment and a gap-closing plan for job seekers.

## Fixes made from these results

| Found | Fix |
|:--|:--|
| The follow task delegated research to 3 subagents (201 searches, $13.52, 12 minutes) | A search budget (~30), no subagents for research, batched verification queries. Re-run: $2.54, 34 searches, under 5 minutes. |
| Python wasn't found when it was installed under a versioned name | Interpreter discovery: `python3`, `python`, `py -3`, `python3.N`, `uv`. Re-run: the scripts ran. |
| A chat summary's counts didn't match the saved file | Summaries must count from the files. |
| An unconfirmed award winner was stated as fact | Time-sensitive claims need a source that states them. |
| The dashboard median included a post with no text | Benchmarks exclude text-less posts and say so. |
| Drafts were much longer than the user's usual posts | The skill flags deliberate departures from the user's style. |
| Claude alone noticed contradictions between profile and posts | Added explicit fact-consistency checks to audit and analyze. |

## Live tests (real sessions, real commands)

After the evals, we drove the plugin like a user would: slash commands, multi-turn conversations, and the commands the evals didn't cover.

| Session | Result | Cost |
|:--|:--|:--|
| `/linkedin:start` → answer its questions → `/linkedin:audit` → `/linkedin:write` (a vet-clinic SaaS founder, 4 turns) | Onboarding found the profile file on its own and asked 4 sharp questions, including German vs English for DACH buyers. The audit and the post reused everything from onboarding without asking again. The post was built from the founder's own sample, with gaps marked. | $0.59 · $1.05 · $2.03 · $2.79 |
| `/linkedin:niche` for an ER nurse moving into healthcare UX | Specific positioning, a scorecard, three sourced white-space angles (nursing AI documentation, ER boarding as a design problem, nurse workarounds), and pillars. Creators it couldn't verify were labeled as unverified leads. | $1.77 |
| `/linkedin:write carousel` from an existing workspace | 9 slides plus a caption scoring 100/100. All slides fit at full size. It flagged its own additions (an illustrative $120k example) for confirmation. | $1.50 |
| `/linkedin:write comment` pushing back on a VP Finance's post | Three options (nuance, counterpoint, question) grounded in the user's own earlier post. No pitch, no invented numbers. | $0.79 |

**Bugs the live tests caught (all fixed, with regression tests where possible):**
- The checker only caught ALL-CAPS placeholders, so `[who covers it, e.g. ...]` could slip through. It now catches any bracketed gap, `XX%`, `TK` and `{{var}}`, without flagging Markdown links.
- Python under a versioned name wasn't found consistently. The skill now runs one exact detection command.
- The `.gitignore` tip repeated in every turn. It's now said once.

## Caveats

- One run per configuration, so these results show direction, not statistical significance.
- The personas are synthetic. Real exports can differ from the fixtures; please report parser misses (see the README).
- The iteration-2 re-runs (follow, analyze) confirmed the cost and Python fixes; they weren't regraded against the full assertion set.
- Assertions about saved files and HTML reports favor the skill by design. The fabrication, accuracy and verification assertions are the discriminating ones.
